# /analyze - Answer Data Questions (SQL Server 2022)

Answer a data question, from a quick lookup to a full analysis to a formal report, using the internal SQL Server 2022 database through the `dbhub` MCP tools.

## Usage

```
/analyze <natural language question>
```

## Workflow

### 1. Understand the Question

Parse the user's question and determine:

- **Complexity level**:
  - **Quick answer**: Single metric, simple filter, factual lookup (e.g., "How many orders came in last week?")
  - **Full analysis**: Multi-dimensional exploration, trend analysis, comparison (e.g., "What's driving the drop in branch sales?")
  - **Formal report**: Comprehensive investigation with methodology, caveats, and recommendations (e.g., "Prepare a quarterly review of our receivables")
- **Data requirements**: Which tables, metrics, dimensions, and time ranges are needed
- **Output format**: Number, table, chart, narrative, or combination

If a company-specific data context skill exists (generated by `data-context-extractor`), load it first and apply its entity definitions, metric formulas and standard filters.

### 2. Gather Data

**If the `dbhub` MCP server is connected (normal case):**

1. Find the relevant tables and columns with `search_objects` (follow the `schema-discovery` skill: names → summary → full)
2. Write T-SQL following the `tsql-queries` skill — SQL Server 2022 syntax only, read-only (`SELECT`/`WITH`), no `DECLARE` or temp tables
3. Execute with `execute_sql`; aggregate on the server, since results are capped at 1000 rows
4. If the query fails, debug and retry (object/column names, schema prefix, type conversions — see "Error Handling" in `tsql-queries`)
5. If results look unexpected, run sanity checks before proceeding

**If `dbhub` is not connected or the server is unreachable:**

1. Suggest `/mssql-setup` to fix the connection
2. Meanwhile, ask the user to provide data in one of these ways:
   - Paste query results from SSMS / Azure Data Studio
   - Upload a CSV or Excel export
   - Describe the schema so you can write T-SQL for them to run
3. Once data is provided, proceed with analysis

### 3. Analyze

- Calculate relevant metrics, aggregations, and comparisons — push heavy aggregation into T-SQL rather than pulling raw rows
- Identify patterns, trends, outliers, and anomalies
- Compare across dimensions (time periods, segments, categories, branches)
- For complex analyses, break the problem into sub-questions and address each

### 4. Validate Before Presenting

Before sharing results, run through validation checks:

- **Row count sanity**: Does the number of records make sense? (`COUNT_BIG(*)` before and after joins)
- **Null check**: Are there unexpected nulls that could skew results?
- **Magnitude check**: Are the numbers in a reasonable range?
- **Trend continuity**: Do time series have unexpected gaps? (Use a `GENERATE_SERIES` date spine to expose them)
- **Aggregation logic**: Do subtotals sum to totals? (`GROUP BY ROLLUP` makes this easy to check)
- **Result truncation**: Did a query hit the 1000-row cap? If so, the result is incomplete — aggregate further

If any check raises concerns, investigate and note caveats.

### 5. Present Findings

**For quick answers:**
- State the answer directly with relevant context
- Include the T-SQL used in a code block for reproducibility

**For full analyses:**
- Lead with the key finding or insight
- Support with data tables and/or visualizations
- Note methodology and any caveats
- Suggest follow-up questions

**For formal reports:**
- Executive summary with key takeaways
- Methodology section explaining approach and data sources (`database.schema.table`, as-of date)
- Detailed findings with supporting evidence
- Caveats, limitations, and data quality notes
- Recommendations and suggested next steps

Respond in the user's language (e.g., Indonesian if they ask in Indonesian); keep T-SQL identifiers as they are in the database.

### 6. Visualize Where Helpful

When a chart would communicate results more effectively than a table:

- Use the `data-visualization` skill to select the right chart type
- Generate a Python visualization (`/create-viz`) or build it into an HTML dashboard (`/build-dashboard`)
- Follow visualization best practices for clarity and accuracy

## Examples

**Quick answer:**
```
/analyze Berapa jumlah transaksi penjualan bulan Oktober 2025?
```

**Full analysis:**
```
/analyze What's causing the increase in support tickets over the past 3 months? Break down by category and priority.
```

**Formal report:**
```
/analyze Prepare a data quality assessment of dbo.Customers -- completeness, consistency, and any issues we should address.
```

## Tips

- Be specific about time ranges, segments, or metrics when possible
- If you know the table names (with schema, e.g. `sales.Orders`), mention them to speed up the process
- For complex questions, Claude may break them into multiple queries
- Results are always validated before presentation -- if something looks off, Claude will flag it
